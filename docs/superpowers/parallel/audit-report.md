# W3-3 mobile, accessibility and brand audit report

Generated by `e2e/audit/audit.spec.ts` (plan [`2026-10-14-2162`](../plans/2026-10/2026-10-14-2162-w3-3-mobile-brand-audit.md))
against every screen in `e2e/audit/screens.ts` at the nine widths **360, 390, 430, 768, 859, 860, 1024, 1280, 1440**
(the plan's phone, tablet, breakpoint-edge and desktop widths; 859 uses the mobile shell, 860 the desktop one).

## What each cell asserts

- `documentElement.scrollWidth <= innerWidth` (1px sub-pixel tolerance) and no in-flow child pushed past its
  parent's box. Elements that `clip` or `scroll` (`overflow-x` ≠ `visible`) are skipped — clipping is the fix,
  and absolutely/fixed positioned children (badges, popovers) are positioned by design.
- Interaction targets pass **WCAG 2.5.5 size-or-spacing** below 860px: either ≥ 44×44px, or spaced so a 44px
  circle centred on the target touches no other target. (Without the spacing alternative the rule would fail
  every 36px button and 40px input in the shipped design system; the pure-size rule is AAA, not AA.)
- axe (`wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`) reports no `serious`/`critical` violation.
  axe's `color-contrast` nodes are re-checked against their own computed foreground/background; a node is
  dropped only when that pair genuinely passes or is the documented brand pair below.
- Tab order reaches the primary action (the first visible control in `main`, or in the open dialog) at 390
  and 1280.
- `prefers-reduced-motion: reduce` leaves no keyframe animation and no transform/opacity transition without
  a `motion-reduce:` opt-out.
- Body copy computes to Inter and display type to Outfit.

## Documented allowances (not bugs)

- **White 14px/600 text on the `brand` fill** is kept by `docs/design/brand.md` ("buttons use 14px/600 text")
  even though it is ~3.6:1. The audit drops exactly that pair and nothing else.
- The **`?mock=` scenario screens** and **`/__kit`** exist only on the standalone mock host / dev build; they
  are listed as `mockOnly` and skipped against the real stack (a production build has no gallery).
- The **"Mock API · default" chip** in the desktop/mobile screenshots is the standalone mock host's debug
  badge; it does not exist against the Rails API.

## How to run

```bash
E2E_AUDIT=1 make e2e ARGS=audit                                   # mock host: the full inventory (all 35 screens)
E2E_API=real E2E_BASE_URL=$(make ports | awk '/web/{print "http://"$2}') make e2e ARGS=audit
```

The audit is opt-in (`E2E_AUDIT=1` or `E2E_API=real`) so the default `make verify` Playwright pass and the
CI `e2e_mock` job stay fast; the report is a deliverable, not a per-PR gate. It also writes the review
screenshots to `e2e/screenshots/audit-<screen>-{390,1280}.png` (git-ignored) for the parity check below.

## Brand and design parity (task 3)

Compared the generated `audit-<screen>-{390,1280}.png` pair with `handoff/design/screenshots/*.png`
(`01-sign-in`, `04-owner-this-week`, `08-pipeline-board`, `16-coordinator-next-actions`, `15-settings`, …),
focusing on the chrome, the auth card, the shells, the KPI/board cards and the overlays.

- **Tokens.** The rose mark is un-tinted; the sidebar/top bar are `bg.surface` on `bg.app`; active nav is
  `brand.tint` + `brand.text`; text is plum/`ink-secondary`/`ink-muted`; the FAB is the only gradient surface.
  Radii match `docs/design/brand.md`: pill controls, 16px row cards, 20px wells/KPIs, 24px auth card/modal,
  bottom sheets `24px 24px 0 0`.
- **Type.** Computed styles are asserted in every cell: body starts with Inter, `font-display` starts with
  Outfit (page titles 24px, KPI 28px, `-0.02em`).
- **Raw hex.** `grep -rnE '#[0-9a-fA-F]{6}' app/javascript | grep -v "ChannelTile\|tailwind\|tokens.css\|\.test\."`
  → **0** lines (only `tokens.css`, `ChannelTile.tsx` and its test contain literals, all excluded by the plan).
- **Layout/behaviour** follows the handoff (sidebar 224px, top bar 56px, FAB bottom-right, mobile tab bar 58px,
  More sheet, full-screen panels); the 859↔860 switch keeps route and open overlays (the audit resizes through
  the edge with a dialog open).

### Intentional deviations (documented in `docs/design/brand.md`, not bugs)

- Brand palette from simbefamily.com replaces the handoff's `#be3a5f`/`#1c1917` values: `brand` `#FF1B5A`,
  `brand.text` `#C8104A`, `brand.tint` `#FAEEEE`, plum `#2E1A28` text, cream `#F4F3EF` wells.
- Type: Inter for UI, **Outfit 600** for display (the handoff used one family).
- Shapes: full-radius buttons/pills/tabs and 16/20/24px cards (the handoff's tighter radii).
- The logo is the flat rose mark from the site, never recoloured or placed in a tinted tile.
- Connect Claude uses the "Generate new key" flow (the handoff's "Reveal" was renamed), and there is no
  "view as" toggle (the handoff sketch had one; the product is single-agency per login).
- `ink-faint` remains the token for placeholders and decorative icons where colour does not carry meaning.

## Limitations

- The audit is run against the **mock host** inventory; the `E2E_API=real` run covers the same routes minus the
  `mockOnly` states (gallery, `?mock=` scenarios, the sign-up steps that would create agencies) and needs
  `E2E_BASE_URL`. The plan's `E2E_API=real make e2e ARGS=audit` line omits that URL; the command above adds it.
- axe's `color-contrast` is sampled per node; the re-check keeps genuine failures but cannot model every
  stacking context (e.g. text under a translucent overlay), so a clean cell is strong evidence, not a proof.
- `make verify` runs the audit only when explicitly gated on, as described above.
