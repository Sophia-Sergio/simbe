## Allowances, exclusions and known issues

This is the authoritative list: nothing below is hidden from the checker, and everything the checker
reports is in the tables at the end of this section.

**What every cell asserts**

- `documentElement.scrollWidth <= innerWidth` (1px sub-pixel tolerance) and no in-flow child pushed past its
  parent's box (elements that clip or scroll are skipped, and absolutely/fixed positioned children are
  positioned by design).
- **Tap targets are at least 44×44 CSS px below 860** — the plan's rule as written (K1). No WCAG 2.5.5
  spacing alternative, no exclusion for fixed/sticky chrome. Every control that still fails is listed by
  screen, width, selector and measured size in the known-issues table.
- axe (`wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`) has no `serious`/`critical` violation (K2).
- Tab order reaches the primary action at 390 and 1280 (the first visible control in `main`, or in the open
  dialog), the focused control shows a visible indicator, and no clipping ancestor cuts that indicator off.
- With `prefers-reduced-motion: reduce` there is no keyframe animation and no transform/opacity transition
  with a non-zero duration (read from computed styles; a `motion-reduce:` class is not trusted).
- Body copy computes to Inter, display type to Outfit.
- Responsive: with the lead panel open, resizing 859 → 860 → 859 keeps the route and the dialog, and the
  panel's scroll offset is never reset while the content still scrolls (it may clamp when the panel becomes
  wide enough that the content fits). Safe-area: the fixed bottom tab bar and the bottom-sheet surfaces
  declare `env(safe-area-inset-bottom)`.

**Allowances (deliberate, documented)**

- **White 14px/600 text on the `brand` pink fill** — `docs/design/brand.md` line 54. The audit drops exactly
  that pair, and only when the interactive host is a real primary button: a `<button>`/`<a>` whose classes
  include `bg-brand text-white rounded-full text-[14px] font-semibold` and whose computed background is the
  brand pink. No other pink surface and no other small text is exempted.
- **Inline links** (WCAG 2.5.5's own inline exception): an `<a>` that flows inside a sentence is not a
  standalone target.
- **Colour transitions are not motion** — `prefers-reduced-motion` is asserted for keyframe animations and
  transform/opacity transitions only.
- **Hover styles are not sampled**: the pointer is parked at (0,0) before measuring, so the resting UI is
  audited. (The danger button's hover darkens rather than lightens, so it cannot drop below AA either.)
- **axe is scoped to the open dialog**: the kit's `useLockBody` marks `#root` inert/aria-hidden while a
  dialog is open, but axe's contrast rule still samples that background. While a dialog is open the audit
  hides `#root` for the measurement and scans the portal only (the reachable part); non-modal screens are
  scanned in full, and the screenshots are taken after the root is restored.
- **A driven screen is reopened when the 860px shell changes** (a page-local dialog unmounts with the page
  behind it on the swap). A stateful drive — the upload-review modal — is driven once, at the first width, and
  the later widths measure the page it leaves behind (the review modal itself is only asserted at 360px).
- **The mock host is shared by two Playwright workers**, so opening a screen retries once on a ready-selector
  timeout; the measurement always runs on the freshly opened screen.
- **A visually hidden control is measured on the label that receives the click.** An `sr-only` radio
  (`QualifiedRadioCards`) is checked through its wrapping label card, not through its 1×1 input. Skips that
  remain, and why: links that flow inside a sentence (WCAG 2.5.5's inline exception); disabled controls
  (`disabled` is not interactive); controls inside an `aria-hidden` subtree (inert content, e.g. the dimmed
  data-sources list while an import is pending); and a visually hidden control with **no** label — the
  dropzone's clipped `<input type=file>` is measured on its visible `role="button"` surface instead.
- The `?mock=` scenario screens and `/__kit` exist only on the mock host / dev build (`mockOnly`); the
  desktop/mobile screenshots show the mock host's "Mock API · default" chip.

**Not asserted**

- Real notch/home-indicator pixel insets: headless Chromium has no safe area, so `env(safe-area-inset-*)`
  resolves to 0. The declaration and the fixed positioning are asserted instead.
- Contrast of hover/pressed/disabled and focus-ring colours (resting state only), and content behind an open
  dialog.
- The upload-review modal at widths other than 360px (its drive is stateful; see the allowance above).
- Browsers other than Chromium.

## Fix history

The first runs found 68 failing cells under the softer rules; the review tightened K1/K2 and this pass fixed
what could be fixed cheaply and listed the rest above.

| Screen | Bug | Fix |
|---|---|---|
| `signup-load-data`, `data-upload`, `kit` | axe `nested-interactive`: the file input sat inside the dropzone's `role="button"` | the input is a sibling of the surface (`Dropzone`) |
| every screen | `prefers-reduced-motion` did not stop the mobile progress pulse / the agent FAB's hover scale | `motion-reduce:animate-none` / `motion-reduce:transition-none` |
| every phone screen | the active tab label used `brand` at 11px (3.6:1) | `brand.text` (≥4.5:1), incl. the More tab |
| `settings`, `search-palette`, lead panel | 11px section/hint text in `ink-faint` (2.6:1) | `ink-muted` |
| `settings` | the Danger button put white 14px/600 on `danger` `#E5484D` (3.9:1) | `danger.text` background, hover darkens (`brightness-90`) |
| `connect` | axe `scrollable-region-focusable` on the MCP config block | `tabIndex={0}` plus `role="region"` |
| `week`, `channels`, `pipeline` | KPI value + delta overflowed at 360 | the value row wraps |
| `pipeline*` | an `sr-only` label escaped the chip scroller and widened the document by 33px at 360 | `relative` on the scroller; pills truncate inside their row |
| `next-actions` | the task action row overflowed at 860/1024; the loading grid used the wrong breakpoint | wrapping row, `min-w-0`, `md:grid-cols-4` (md = 860) |
| `agent-panel` | a starter chip was 3px wider than its wrap row at 360 | `Chip` gains a `multiline` mode |
| all kit controls | 36px buttons / 40px inputs / 28px segmented items below 860 | `h-11 md:h-9` / `h-11 md:h-10` / `min-h-11 md:min-h-0` (plus `min-w-11` for icon-only and segmented controls, `min-h-11` for back links and small text buttons) |
| `Segmented` | `overflow-x-auto` clipped the 2px outline (offset 2px) and the selected item's shadow | the items use an inset focus outline (`focus-visible:-outline-offset-2`); the audit fails when a focus ring is clipped |
| lead-panel tabs | the unselected tab label was `ink-muted` on `bg-subtle` (4.29:1) | `ink-secondary` |
| pending data sources | the dimmed CRM list was `ink-muted` at 50% (3.2:1) | `text-ink` row counts at `opacity-70` (≥4.5:1) |
| `AppShell` | the 859↔860 shell swap unmounted the open overlay and lost its scroll | overlays are rendered outside the shell branch (they portal to `body`) |

## Desktop-visible changes this audit contains

Everything below is visible at ≥860px as well, not only on phones. (`md:` is this project's 860px
breakpoint — `tailwind.config.ts` overrides `screens.md` — so the `md:` classes below are the desktop side.)

| Element | Change (all widths unless stated) |
|---|---|
| `Button` danger | `bg-danger-text` (was `bg-danger`) so white 14px/600 clears AA; hover darkens via `brightness-90` |
| `Tabs` unselected, `Segmented` unselected | `text-ink-secondary` (was `text-ink-muted`), which fixes `ink-muted` on the `bg-subtle` track at 4.29:1 |
| `Segmented` track | `gap-0.5` → `gap-1`, plus `max-w-full overflow-x-auto` so a narrow toolbar scrolls the track instead of widening |
| `Segmented` / `Chip` focus ring | inset (`focus-visible:-outline-offset-2`, no `md:` prefix) so a scrolling ancestor cannot clip the 2px outline |
| KPI value row | wraps (`flex-wrap`) so a long delta cannot overflow a 360px card |
| Heavier touch targets | **only below 860** (`h-11 md:h-9`, `h-11 md:h-10`, `min-h-11 md:min-h-0`): desktop keeps 36px buttons, 40px inputs and 28px segmented items |
| Data-sources pending list | row counts are `text-ink` inside `opacity-70` (was `ink-muted` at `opacity-50`, 3.2:1) |
| Overlays | rendered outside the shell branch (still portals to `body`); no visual change, the 859↔860 swap no longer unmounts an open panel |

## Brand and design parity

Compared the generated `audit-<screen>-{390,1280}.png` pair with `handoff/design/screenshots/*.png`
(`01-sign-in`, `04-owner-this-week`, `08-pipeline-board`, `16-coordinator-next-actions`, `15-settings`, …).

- **Tokens.** The rose mark is un-tinted; sidebar/top bar are `bg.surface` on `bg.app`; active nav is
  `brand.tint` + `brand.text`; the FAB is the only gradient surface. Radii match `docs/design/brand.md`
  (pill controls, 16px rows, 20px wells/KPIs, 24px auth card/modal, `24px 24px 0 0` sheets).
- **Type.** Computed styles are asserted in every cell: body starts with Inter, `font-display` with Outfit.
- **Raw hex.** The plan's exact command
  `grep -rnE '#[0-9a-fA-F]{6}' app/javascript | grep -v "ChannelTile\|tailwind\|tokens.css\|\.test\."`
  was run in the web container and printed **nothing** (exit 1 — no matching line). Without the exclusions it
  only matches `styles/tokens.css`, `ChannelTile.tsx` and `ChannelTile.test.tsx`, which the plan excludes.

### Intentional deviations (documented in `docs/design/brand.md`)

Brand palette from simbefamily.com replaces the handoff's values (`brand` `#FF1B5A`, `brand.text` `#C8104A`,
`brand.tint` `#FAEEEE`, plum text, cream wells); Inter for UI and **Outfit 600** for display; full-radius
pills and 16/20/24px cards; the flat rose mark never recoloured or placed in a tinted tile; Connect Claude
uses "Generate new key" (the handoff's "Reveal" was renamed); no "view as" toggle (single agency per login).

## Limitations

- The audit runs on Chromium only; the checker measures the DOM geometrically, so it cannot model every
  stacking context.
- The real-mode run needs a seeded stack (`rails e2e:seed`) and `E2E_BASE_URL`; the plan's Done-when line
  omits the URL.
