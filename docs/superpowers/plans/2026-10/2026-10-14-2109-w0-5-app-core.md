## Global Constraints
- Nothing in this plan renders feature screens; it only assembles what `registry` returns.
- Routes carry `handle: { roles?: Role[]; title?: string }`; `title` is shown by the mobile top bar.
- Passwords are never stored client-side.
- Coordinator → `/next-actions`; owner → `/` when a role guard rejects.

## Review Focus
- Cold load of `/pipeline` while signed out → `/signin?next=/pipeline`, and back after sign-in.
- 401 from any query while authenticated (expired cookie) → clears the cache and returns to sign-in once (no redirect loop).
- Two overlays opened at once (search over lead panel) never happens: opening search closes the lead panel (`useSearchPalette.open` calls `useLeadPanel().close()`).
- `/` for a coordinator and `/next-actions` for an owner both redirect to their home without flashing the wrong screen.
- Provider order from features is deterministic.
