## Overrides
1. **Fake tools for parallel work**: until B-AGENT merges, specs use `spec/support/fake_agent_tools.rb` (this lane's file), which defines a stand-in `Agent::Tools` **only when the real one isn't loaded** (`unless defined?(Agent::Tools)`) with exactly the contract: `NAMES` (five names), `mcp_definitions` (five `{name, description, inputSchema}`), `call(name, input, agency:, user:)` (returns `{ stages: [10,5,4,3,2,1] }`-style canned data for `get_funnel`, raises `Agent::Tools::Error` for unknown names/bad input). After B-AGENT merges, the same spec file must pass with the real registry: run once with `USE_REAL_TOOLS=1`.
2. **Routes**: `/mcp/:slug` goes in `app/packs/mcp/config/routes_root/mcp.rb` (outside `/api/v1`); settings routes (`GET /mcp`, `POST /mcp/rotate`) in `app/packs/mcp/config/routes/mcp.rb`; throttle (60/min/key) in `app/packs/mcp/config/rack_attack/mcp.rb`.
3. **No migration**: `mcp_keys` exists from W0-3.
4. The JSON-RPC endpoint is not in OpenAPI, so only the two settings operations use conformance validation; the RPC spec asserts the JSON-RPC envelopes by hand (`initialize`, `tools/list` = the five names, `tools/call` scoped to the key's agency, `-32601`, `-32700`, 202 for notifications, 401 wrong key, 404 slug/key mismatch, rotation revokes the old key, full key shown once and only a digest stored).
5. Settings fixture parity: `getMcpSettings` equals the shape of `contracts/examples/mcp/settings.json`; `rotateMcpKey` returns `{ key, url, key_prefix }` with the key prefix equal to `key_prefix` and `url` built from `ENV["MCP_PUBLIC_URL"]` + `/<slug>`.

## Global Constraints
- Keys are `simbe_live_<32 urlsafe chars>`, stored as SHA-256 digests with a visible prefix; constant-time compare; owner-only settings; batch JSON-RPC rejected (`-32600`).
