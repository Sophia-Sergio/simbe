## Overrides
1. Layout per handoff §11: left card (Server URL + API key read-only monospace fields, dark `bg-dark` JSON config block `rounded-[10px]`), right card "Tools Claude can use" (monospace `text-brand-text` names + descriptions): `get_funnel`, `get_channel_performance`, `get_dropoff_reasons`, `get_next_actions`.
2. **Key handling**: the page shows only the masked prefix (`simbe_live_ab12•••…`); **Generate new key** opens an **inline** `ConfirmInline` ("This revokes the current key immediately."), then shows the full key once with Copy, a "shown only once" notice and the config block with `Authorization: Bearer <that key>`; leaving the page discards it (nothing stored client-side). The prototype's "Reveal" button is intentionally not built.
3. Config JSON: `{"mcpServers":{"simbe":{"url":"<url>","headers":{"Authorization":"Bearer <key | YOUR_KEY>"}}}}`; Copy buttons toast "Copied".
4. Mock: `GET /mcp` → `settings.json` (`key_prefix: null` under `?mock=new` shows "No key yet — generate one"); `POST /mcp/rotate` returns a fresh random key; second concurrent rotate → 409 message "A key is already being generated."

## Responsive acceptance
- **Desktop:** two columns (`1fr / 1fr`): connection card left, tools card right.
- **Mobile:** stacked; code block scrolls horizontally *inside* the block only (page itself must not scroll horizontally); Copy buttons ≥ 36px; the inline confirm stays within the card.
