## Overrides
1. `UploadModal` states (spec decision 6): dropzone → "Validating files" (pulsing 2px line, from `state === "validating"`) → "Review changes" (`ReviewReport`; **Replace snapshot** disabled when `report.ok === false`) → success toast "Snapshot replaced · no duplicates counted"; Cancel calls `cancel()` (DELETE). Replace is single-flight; `409 already_in_progress` shows "A load is already running — try again in a minute."
2. Connector cards (Meta, Google): Connect / Connected (green pill-button) with note "Sample spend — live sync coming"; disconnect via an inline `ConfirmInline` (not a dialog).
3. "CRM exports" card: `Loaded <date, time in agency tz>` and the seven rows (green dot, file name, row count) from `getCurrentSnapshot().files`; empty state when `snapshot: null` ("No data loaded yet") with the primary **Upload new snapshot** button.
4. Mocks: `?mock=empty` for the empty state; the default mock walks `upload-ok.json` → `commit.json`; dropping only six files yields `upload-errors.json` (red rows, Replace disabled).
5. After a successful commit the lane relies on the hook's invalidations (no manual refetch).

## Responsive acceptance
- **Desktop:** header with primary button, connector cards side by side, CRM exports card; upload is a centered modal (max 480px).
- **Mobile:** connectors stack; the upload UI is a **bottom sheet** (kit `Modal`), review rows wrap, Replace/Cancel buttons full width in a sticky footer; no horizontal scroll.
