## Overrides
1. **Facts**: Task 5's importer calls the existing `Snapshot::Facts.call(agency_id)`; do not recreate it.
2. **Routes/isolation**: routes go in `backend/config/routes/snapshots.rb`; isolation entries in `backend/spec/support/isolation/snapshots.rb` (`Isolation.register(...)`). No other shared file is edited.
3. **Real-data load (Task 6)**: do not edit `docker-compose.yml`. Run with a one-off mount:
   `docker compose run --rm -v "$PWD/harbor-takehome:/harbor-takehome:ro" api bundle exec rails "snapshot:load[harbor,/harbor-takehome/exports/harbor]"`.
4. **Contract shape**: `GET /snapshots/current` returns `files: [{name, rows}]` using the export file names (`leads.csv`←leads, `stage_history.csv`←stage_events, `contact_log.csv`←contacts, `screener_answers.csv`, `web_sessions.csv`, `appointments.csv`, `applications.csv`) derived from `snapshots.row_counts`; the report's `diff` keys are the table names; `ignored` lists unmatched upload names. Request specs run with OpenAPI conformance on.
5. Spec data: validator/importer specs build exports with `AlphaScenario.copy_dir`; request specs may seed an existing snapshot with `AlphaScenario.load!` where the plan used the importer.

## Global Constraints
- Re-loading the same files leaves identical row counts; a failure rolls back to the previous snapshot; one advisory lock per agency (`409 already_in_progress`).
- Owner-only; other agencies' upload ids → 404.
- `unscoped` only inside `app/services/snapshot/**`.
