## Overrides
1. **Everything heavy runs in jobs on the `ingest` queue** (1 worker thread, Solid Queue in Puma). The controller only stores files (`Snapshot::Storage`), creates the `snapshot_uploads` row and enqueues:
   - `POST /snapshot_uploads` → `201 {id, status: "validating", progress {phase: "storing", pct: 0}, report: null, snapshot: null, error: null}`; `Snapshot::ValidateUploadJob` parses (via `Snapshot::Reader`), validates, writes `report`, sets `status: validated`.
   - `GET /snapshot_uploads/:id` → the `SnapshotUpload` shape (owner only; other agencies' ids → 404), including `progress {phase, pct, rows_done, rows_total}` updated by the jobs through `Snapshot::Progress` (throttled: write at most every 500 ms or +1%).
   - `POST /snapshot_uploads/:id/commit` → `202` + status `committing`; `409 not_validated` if validation hasn't finished; `422 invalid_snapshot` (with the report) when `report.ok` is false; `409 already_in_progress` when the agency already has a validating/committing upload (enforced by the partial unique index + a rescue of `ActiveRecord::RecordNotUnique`, plus the advisory lock inside the job).
   - `Snapshot::CommitUploadJob` re-reads the stored files, runs the importer inside **one transaction** (advisory xact lock per agency → delete the agency's leads (children cascade) → batch insert 5,000 rows → `Snapshot::Facts` → `snapshots` row with `as_of` from `Snapshot::AsOf`), sets `status: committed` + `snapshot_id`, deletes the stored files. Any exception rolls back, sets `status: failed` with `error {code, message}` (no stack traces, no row contents), and leaves the previous snapshot intact.
   - `DELETE /snapshot_uploads/:id` → cancels (status `cancelled`, files removed; a running job checks the flag between batches and aborts); `expire_uploads_job` (recurring, hourly) expires uploads older than 24 h.
   - `GET /snapshots/current` adds `pending` (the agency's in-flight upload as `{upload_id, status, progress}` or `null`) and `files: [{name, rows}]` from `row_counts` using the export file names (`stage_history.csv`←stage_events, `contact_log.csv`←contacts, …).
2. **No cross-agency logic.** There is no `foreign_lead` rule and the validator and importer never query another agency's rows. The only agency check is `agency_mismatch` against **this** agency's own existing snapshot (≥ 50% overlap of external ids). `unscoped` is allowed only inside `app/services/snapshot/**` to delete/replace **this** agency's rows.
3. **Same files, many agencies**: a spec loads the identical Alpha CSVs through the API for two different agencies (two owners) and asserts two independent snapshots with equal counts and no mention of each other in any report.
4. **`as_of`** comes from `Snapshot::AsOf` (latest event timestamp; ignores `scheduled_for`/`paused_until`): a spec with an appointment `scheduled_for` in the future proves it.
5. **Report content** equals the shapes in `contracts/examples/snapshots/upload-ok.json` and `upload-errors.json`: `diff` per table (`current/incoming/delta`), `checks {files_matched "7 of 7", duplicates, screener_encrypted}`, warnings with the count semantics in spec `2002` decision 7 (`duplicate_email` = extra rows; `source_aliases_normalized` = non-canonical spellings; `stage_mismatch`), `ignored` for unmatched file names.
6. **Performance**: parsing and import stream by file and by table (no whole-CSV arrays, no per-row model instantiation except screener encryption in 5,000-row slices; consider `COPY` for non-encrypted tables). Lakeside (69 MB, ~625k rows) must import in **< 120 s** on a laptop; the real-data spec prints phase timings.
7. **Routes/isolation**: `app/packs/ingest/config/routes/snapshots.rb`; isolation entries in `spec/support/isolation/snapshots.rb`. Request specs run with OpenAPI conformance on and use `perform_enqueued_jobs` (or `queue_adapter = :inline`) to drive the jobs; add one spec that uses the real Solid Queue adapter to prove a job runs inside Puma's supervisor config.
8. **Data in specs**: `AlphaScenario.copy_dir` for CSV paths; `AlphaScenario.load!` only to pre-seed an existing snapshot.

## Global Constraints
- Owner-only; other agencies' upload ids → 404; coordinators 403. One in-flight job per agency. Re-loading the same files leaves identical row counts. Never log row contents or answers. Files in `storage/snapshot_uploads/<id>/` are deleted after commit/cancel/expiry.

## Review Focus
BOM/CRLF CSVs; blank → NULL; failure on the last table rolls everything back; two simultaneous commits; a cancelled upload mid-import; browser closed mid-job (job still finishes, `GET` later shows `committed`); a 69 MB multipart upload (Rack limits, `250 MB` cap → `413`); worker restart mid-job (status becomes `failed`, previous snapshot intact — a boot-time sweeper marks stale `committing` rows older than 30 min as `failed`).
