## Overrides
1. **Board endpoint**: the contract splits the board out: `GET /leads/board` (`getBoard`, optional `coordinator`) and `GET /leads` (`listLeads`: `status`, `coordinator`, `q`, `cursor`, `per`). Drop the plan's `view=board|list` switch and the per-column cursor loader. A `q` request without a cursor returns at most 8 results.
2. **Data in specs**: `AlphaScenario.load!(agency)` instead of the importer.
3. **Queues**: use `Leads::Queues.call(...)`/`SQL_CTE` and `Leads::Access.relation(user)` from W0-3; do not redefine them.
4. **Detail shape** equals `contracts/examples/leads/detail-owner.json` / `detail-coordinator.json` for Alpha lead L4 (a spec asserts the owner and assigned-coordinator responses equal those fixtures after JSON round-trip, including masked vs unmasked phone, `can_contact`, and `answer` present only for the coordinator). Board response equals `board.json`; list (open, owner) equals `list.json`.
5. **Routes/isolation**: `app/packs/leads/config/routes/leads.rb`; isolation entries in `spec/support/isolation/leads.rb` (`GET /api/v1/leads/:id`, `GET /api/v1/leads`, `GET /api/v1/leads/board`).
6. Request specs run with OpenAPI conformance on.

7. **Real-data oracle** (`spec/real_data/leads_golden_spec.rb`, tag `:real_data`): for `harbor` and `lakeside` (agency config from `RealData::CONFIG`, data via `RealData.load!`, owner session) assert against `Golden.agency(slug)`: `GET /leads/board` → `columns.{action_needed,in_application,consult,qualified}.count` equal `board_column_counts` (Harbor 90/11/15/321, Lakeside 449/68/122/4,112) with ≤ 25 cards per column; walking `GET /leads?status=open` through `next_cursor` returns exactly `outcomes.open` leads with no duplicates; `status=paused` → `outcomes.paused`, `status=closed` → not_eligible + withdrew + unresponsive, `status=accepted` → `outcomes.accepted`; each page < 500 ms; `GET /leads?q=` on a name taken from the data returns that lead only for the owner and, for a coordinator session of another coordinator, nothing; the detail endpoint for any lead exposes **no** `answer` key for the owner (scan the JSON of 50 random leads). Changing the agency definition re-columns the board (`qualified` equals the golden `qualified_by_milestone` restricted to open|accepted leads — assert against `qualified_all_time` where the outcome filter makes no difference, otherwise just assert the sum of columns changes consistently).

## Global Constraints
- Coordinators only see `leads.coordinator_name = user.coordinator_name` (others → 404). Raw screener answers only for the assigned coordinator (plus `age` for both roles); phone masked otherwise; no answers in logs.
- `q` escapes `%`, `_` and quotes (`sanitize_sql_like`).
