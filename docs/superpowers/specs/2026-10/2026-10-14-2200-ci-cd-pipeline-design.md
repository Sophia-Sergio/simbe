# CI/CD pipeline (GitHub Actions → Fly.io) and agent-friendly repo workflow — Design

> **Layout superseded by [`2300-rails-monolith-and-packs`](./2026-10-14-2300-rails-monolith-and-packs-design.md):** the app is one Rails monolith with embedded React (`vite_rails`) and backend packs; paths below were migrated mechanically (`app/packs/<pack>/…`, `app/javascript/…`). Product and process decisions here still stand.

**Status:** Approved for planning · **Depends on:** `2100` (lanes), appketing's `.github/workflows/ci.yml`, `fly.toml`, `Dockerfile`, `bin/worktree-env` as the reference · **Plan:** `plans/2026-10/2026-10-14-2201-w0-7-ci-cd-pipeline.md`

## Goal
One pipeline that (1) gives every lane PR fast, trustworthy feedback — security scans, lint, contract checks, frontend tests, mock-mode e2e with screenshots, lane-ownership check — and (2) deploys `main` to production on Fly.io after everything is green, exactly the way appketing does, adapted to Simbe's Rails API + React SPA monorepo. It also gives many parallel agents isolated local stacks.

## Findings (appketing, the reference)
- One workflow `ci.yml` on `pull_request` and `push: main`; a **`decide`** job skips re-running CI on `main` when the merged PR's head commit already passed; parallel jobs `brakeman`, `bundler_audit`, `scan_js` (npm audit), `knip`, `lint` (+ `boundaries:check`), `test` (Postgres service, parallel RSpec); **`deploy`** (Fly, `--remote-only --depot --ha=false`, `--release-command-timeout 20m`, concurrency group `deploy-production`, never cancelled) only on `main` when every check passed; then a **post-deploy `/up` poll**. Dependabot monthly, grouped minor/patch. `fly.toml`: `release_command = bundle exec rails db:prepare`, `/up` health check, scale-to-zero, non-root image on :8080 with Thruster, jemalloc. **Simbe differs on scaling:** imports of the real exports (up to 69 MB / ~625k rows) run as background jobs inside the web process, so the machine must not scale to zero (`auto_stop_machines = off`, `min_machines_running = 1`) and needs 2 GB RAM.
- appketing isolates each git worktree's Docker stack with `bin/worktree-env` (own compose project, database and Docker-assigned ports) — essential when many agents run Compose on one machine.
- Simbe differences: Rails is **API-only** and the SPA is a separate Vite build; health data (encrypted screener answers) raises the bar on secrets, backups and "never commit exports"; contract/mocks/ownership checks are new (spec `2100`/`2101`).

## Decisions
1. **Single workflow `ci.yml`** with the appketing structure. Jobs (all parallel after `decide`): `contract` (bundle + lint, generated types up to date, `check-ownership.sh`), `brakeman`, `bundler_audit`, `npm_audit`, `knip` (unused frontend code/deps), `lint_backend` (RuboCop + `boundaries:check`), `lint_frontend` (ESLint + `tsc --noEmit`), `test_backend` (RSpec on a Postgres 16 service with OpenAPI conformance; uploads the contract-coverage report), `test_frontend` (Vitest incl. mock-conformance), `e2e_mock` (Playwright desktop+mobile against the Vite dev server in mock mode; **screenshots always uploaded** for PR review), `e2e_real` (full stack on real Rails + Solid Queue; every lane's e2e plus the upload-at-signup journey using a **synthetic** Harbor-shaped export from `bin/generate-sample-export`; the real exports are never in CI, so `@real` tests are skipped; `continue-on-error` until W3-1 lands, then required), `guards` (no exports/`.env`/CSVs/secrets committed, `golden.json` is valid, lane tooling loads), `ownership_check` (PRs from `lane/*` branches), `docker_build` (builds the production image, no push). `deploy` needs all required jobs.
2. **Triggers and concurrency**: PR runs cancel superseded runs of the same PR (`concurrency` with `cancel-in-progress` for `pull_request`); `main` runs never cancel deploys. `permissions: contents: read` (+ `pull-requests: read`, `actions: read` as appketing).
3. **Deploy**: Fly.io app `simbe`, `flyctl deploy --remote-only --depot --depot-scope=app --ha=false --app simbe --release-command-timeout 20m`, secret `FLY_API_TOKEN` in a GitHub **environment `production`** (optional required reviewer — recommended given health data). After deploy poll `https://<app>.fly.dev/up` (20×3s) **and** `GET /` (must contain the SPA shell) **and** `GET /api/v1/me` → `401` JSON (proves the API and SPA fallback routing). Rollback = `fly releases` + redeploy the previous image (runbook).
4. **Production image** (multi-stage, mirrors appketing): Ruby slim base with jemalloc + libpq; build stage installs gems, builds the embedded React app with Node 22 as part of `rails assets:precompile` (`vite_rails`; output `public/vite`); final image non-root (uid 1000), `RAILS_ENV=production`, `RAILS_SERVE_STATIC_FILES=true`, Thruster on `:8080`. The shell page and **SPA fallback** are Rails-rendered by `SpaController` (layout with Vite tags; shipped in W0-1): any `GET` that is not `/api/*`, `/mcp/*`, `/up` or a static file renders it, unknown `/api/*` is a JSON 404.
5. **Config & secrets** (Fly secrets, never in the repo): `SECRET_KEY_BASE`, `DATABASE_URL`, `AR_ENCRYPTION_PRIMARY_KEY`, `AR_ENCRYPTION_DETERMINISTIC_KEY`, `AR_ENCRYPTION_KEY_DERIVATION_SALT` (**losing these makes stored screener answers unreadable — back them up in a password manager, runbook step**), `ANTHROPIC_API_KEY`, `APP_URL`, `MCP_PUBLIC_URL`. Non-secret env in `fly.toml`. Region default `ord`; VM `shared-cpu-2x`/2 GB (between Pacific and Central agencies; adjustable). Database: any managed Postgres 16 reachable through `DATABASE_URL` with daily backups (default recommendation: Fly's managed Postgres in the same region — confirm the current product name/pricing in Fly's docs when provisioning); `release_command = bundle exec rails db:prepare`.
6. **Dependabot** monthly, grouped minor/patch, for `bundler` (`/`), `npm` (`/`), `github-actions`, `docker`.
7. **Repo hygiene for many agents**: PR template with the lane checklist (Done-when outputs, desktop+mobile screenshots, ownership clean, no contract change); labels `lane`, `wave-N`, `ccr`, `e2e`; issue template **Contract Change Request** and **Lane blocked**; `CODEOWNERS` routing `contracts/**` and `.github/**` to the repo owner; `bin/setup-github` script (labels, branch protection, merge settings) that is **documented and dry-run by default** — applied by the repo owner, never automatically.
8. **Branch protection (applied by the owner)**: `main` requires a PR, the required checks (`contract`, `brakeman`, `bundler_audit`, `npm_audit`, `knip`, `lint_backend`, `lint_frontend`, `test_backend`, `test_frontend`, `e2e_mock`, `guards`, `ownership_check` when applicable, `docker_build`), up-to-date branch, linear history via squash merge, auto-delete merged branches, no force pushes. `e2e_real` becomes required after W3-1.
9. **Local = CI**: every command a CI job runs is part of `make verify` (checked by `bin/ci-parity`), so an agent that passes `make verify` passes CI except environment-only jobs (`docker_build`, `deploy`, `e2e_real`). Per-worktree isolation: `bin/worktree-env` + Makefile `worktree-guard`, `worktree-env`, `ports` (compose uses `${API_PORTS}`, `${WEB_PORTS}`, `${DB_PORTS}`, `${POSTGRES_DB}`); e2e reads the assigned URL from `docker compose port web 5173`.
10. **Guards for sensitive data and the real-data oracle**: the only real data (`handoff/takehome/exports/`) is local-only (`docs/conventions/real-data.md`); CI also fails if `spec/real_data/golden.json` is not valid JSON; `:real_data` RSpec tags and `@real` Playwright tags are skipped in CI by construction. Beyond that,  CI fails if any tracked path matches `handoff/takehome/exports/(harbor|lakeside)/`, any tracked `.env*` other than `.env.example`, any tracked `*.csv` outside `spec/fixtures/` and `contracts/`, or `gitleaks` finds a secret (config allow-lists the dummy test keys).
11. **Agent tooling**: `opencode.json` (loads `AGENTS.md` automatically; `instructions` globs for `docs/conventions/*.md` and `docs/design/brand.md`; permission rules: ask before `git push`, deny destructive `rm -rf` / `docker system prune` / pushing to `main`), Cursor rule `lanes.mdc` (lane ownership + commit-per-task), and the playbook (`docs/superpowers/parallel/playbook.md`).
12. **Speed budget**: wall-clock ≤ 12 minutes on a PR (jobs parallel, dependency + Playwright browser caches, RSpec `parallel_tests`, Vitest threads); `e2e_real` may take longer and runs only on `main`, on PRs labelled `e2e`, and nightly.

## Non-goals
Staging environment (design leaves room: `fly.staging.toml` + a second deploy job), blue/green or canary releases, Terraform/IaC, APM/Sentry (optional later), multi-region, scheduled data loads, HIPAA/BAA compliance work (flag with counsel before real patient data).

## Acceptance criteria
1. `npx --yes actionlint .github/workflows/ci.yml 2>&1 | tail -1` (or `docker run --rm -v "$PWD":/r -w /r rhysd/actionlint`) reports no errors; `python3 -c "import yaml,sys; yaml.safe_load(open('.github/workflows/ci.yml'))"` exits 0.
2. `docker build -t simbe:test . && docker run --rm -d -p 8080:8080 --name simbe-test -e SECRET_KEY_BASE=x -e DATABASE_URL=postgres://u:p@host.docker.internal/x simbe:test` then `curl -fs localhost:8080/up`, `curl -fs localhost:8080/ | grep -qi '<div id="root">'` and `curl -s -o /dev/null -w '%{http_code}' localhost:8080/api/v1/me` → `401` (SPA fallback and API both served by one image).
3. `make spec ARGS=spec/requests/spa_spec.rb` passes (HTML fallback for `/pipeline` and `/channels/Facebook`, `404` JSON for unknown `/api/v1/x`, `/up` unaffected, `/mcp/x` not swallowed).
4. `flyctl config validate --config fly.toml` exits 0; `grep -E 'release_command|/up' fly.toml` shows both.
5. `bin/ci-parity` exits 0 (every command in `.github/workflows/ci.yml` `run:` blocks that is marked `# parity` appears in `make verify`).
6. `bin/setup-github --dry-run` prints the labels and the branch-protection payload without calling the API; `bin/setup-github` refuses to run without `--apply`.
7. `bash docs/superpowers/parallel/check-ownership.sh && bin/lane list | wc -l` succeed in CI's `contract` job; a PR from a `lane/*` branch that edits an unowned file fails `ownership_check` (verified once with a throwaway PR).
10. `python3 bin/generate-sample-export --out /tmp/syn --leads 500 && ls /tmp/syn | wc -l` prints `7`, and in the `e2e_real` job the synthetic upload journey reaches `Your data is loaded` (async import in CI) with the artifacts attached.
8. `git ls-files | grep -E 'handoff/takehome/exports/(harbor|lakeside)/|(^|/)\.env($|\.)' | grep -v '.env.example' | wc -l` prints `0`, and the `guards` job fails when a fixture violating that is added on a scratch branch (verified once).
9. After the first merge to `main` with secrets configured: the `deploy` job succeeds and its health step prints `GET /up returned 200`, `GET / returned the SPA shell`, `GET /api/v1/me returned 401`.
